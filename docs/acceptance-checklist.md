# Чек-лист приёмки, фазы 0–4

Фаза принята, когда отмечены все её пункты, `npm run build`, `npm run lint` и `npm run test:run` зелёные, фаза задеплоена.

## Фаза 0 — уборка

- [x] Нет «Указать списание» и дней зарплаты: ни в интерфейсе, ни в схеме, ни в коде.

## Фаза 1 — пространство

- [ ] Таблицы пространств и участников (роль владелец/участник); у трат и категорий `space_id` и `created_by`.
- [ ] Миграция создала каждому существующему пользователю пространство и перенесла его данные; имя категории уникально в пространстве.
- [ ] `spaceId` определяется в одном месте DAL рядом с `requireSession`; все репозитории принимают `spaceId`.
- [ ] Integration-тест изоляции: участник пространства A не видит траты и категории пространства B.
- [ ] Настройки: блок «Совместный доступ» со списком участников (имя, email); у владельца кнопка «Создать ссылку» с копированием; ссылка одноразовая, новая отменяет старую.
- [ ] Страница приглашения: регистрация email+пароль или Google; после подтверждения почты новый пользователь участник пространства без своего; токен погашен; недействительный токен показывает ошибку; регистрация без токена создаёт своё пространство.
- [ ] Валюта отображения и подсказки формы личные.
- [ ] Правка категорий: долгое нажатие или правый клик по категории в форме траты открывает окно (название, цвет; удаление только у категории без трат); раздела «Категории» в настройках нет.
- [ ] Проверка на проде: второй человек регистрируется по ссылке со своего телефона, видит общие траты и категории, добавляет трату, первый её видит.

## Фаза 2 — списки, навигация и новый визуал

- [ ] Нижняя панель на всех продуктовых экранах: «Траты», «История», «Списки».
- [ ] Экран «Списки»: перечень (название, отмечено из всего, пометка приватности), создание с выбором «Виден только мне», порядок по последнему изменению.
- [ ] Экран списка: пункты с галочками, отмеченные внизу; добавление пункта; долгое нажатие или правый клик открывает правку пункта (изменить текст, удалить); «Сбросить галочки», переименование, переключение приватности, удаление списка.
- [ ] Пункт — только текст.
- [ ] Таблицы списков и пунктов со `space_id`, `created_by`, `visibility`.
- [ ] Integration-тест: участник B не видит приватный список A; оба видят общий; участник другого пространства не видит ничего.
- [ ] Панель навигации и экраны списков совпадают с холстом.
- [ ] «Траты», «История», «Настройки» и карточка траты совпадают с холстом: токены в `globals.css`, нижние окна без крестика, знак валюты справа в полях суммы, окно выбора валюты, пустые состояния.
- [ ] Проверка на проде с двух телефонов: общий список покупок, изменения видны после обновления экрана.

## Фаза 3 — счета

- [ ] Вкладка «Счета» в панели.
- [ ] Экран: переключатель валюты отображения в шапке; итог по счетам в валюте отображения по курсам на сегодня; счета по убыванию суммы; добавление (название, валюта из пяти, остаток); правка названия и остатка; удаление с подтверждением.
- [ ] Таблица счетов: `space_id`, `created_by`, `name`, `currency`, `anchor_amount_minor`, `anchor_at`.
- [ ] Integration-тест изоляции по пространству; unit-тест итога в валюте отображения.

## Фаза 4 — связь трат и счетов

- [ ] У траты `account_id` (обязательный, счёт того же пространства); удаление счёта удаляет его траты, подтверждение называет их число. Старым тратам без счёта миграция заводит счёт «Основной» на валюту с остатком 0.
- [ ] В форме выбор счёта вместо сегмента валют: выбранный счёт задаёт валюту; по умолчанию последний счёт автора. Счетов нет → поля и кнопка «Добавить трату» неактивны, ссылка «Создайте первый счёт».
- [ ] Остаток = якорь минус траты счёта, записанные после момента якоря (по времени создания записи); «уточнить остаток» ставит новый якорь.
- [ ] Тесты: создание, правка суммы, перенос на другой счёт и удаление траты меняют остаток верно; траты, записанные до якоря, на остаток не влияют.
- [ ] Экран счетов показывает остатки по формуле.
