# moneta — бизнес-спека (MVP)

## 1. Что это и для кого

**moneta** — личный трекер расходов. Каждый зарегистрированный пользователь
ведёт свои траты в изолированном аккаунте. Цель — за 5–10 секунд внести трату
с телефона или компьютера и в любой момент увидеть, сколько и на что я трачу.

**Аудитория:** любой, кому нужен простой персональный учёт расходов.
Это не multi-tenant SaaS с командами, шарингом или ролями — каждый юзер
использует приложение лично для себя; просто регистрация открыта.

## 2. Цели MVP

Минимально жизнеспособная версия должна:

1. Дать **внести трату** за один экран: сумма, категория, описание, дата
   (по умолчанию — сегодня).
2. Дать **создать категорию налету** прямо из формы траты — без перехода куда-то
   ещё.
3. Показать **сводку за период** — общий итог, разбивку по категориям и по дням,
   с редактированием/удалением трат.
4. **Сохранять данные** между сессиями и устройствами (синк через Postgresql).
5. **Работать с телефона как PWA** — установка на главный экран, отзывчивый UI.

## 3. Что НЕ делаем в MVP (не-цели)

Чтобы не растечься, явно вычёркиваем:

- 🚫 **Доходы.** Только расходы. Income можно добавить позже отдельной сущностью.
- 🚫 **Бюджеты и лимиты.** Никаких «лимит на еду 10 000 в месяц / 80% израсходовано». Но после MVP появится – нужно продумать архитектуру с возможностью расширения.
- 🚫 **Повторяющиеся траты.** Никаких подписок / автокатегоризации.
- 🚫 **Несколько валют.** Только рубли. (Поле `currency` в БД оставим на будущее,
   но UI пишет ₽.)
- 🚫 **Несколько счетов / кошельков.** Всё в одной куче.
- 🚫 **Импорт банковских выписок** / интеграция с банками.
- 🚫 **Фото чеков, OCR.**
- 🚫 **Команды / семейный аккаунт.** Никаких приглашений, расшаривания
   категорий или трат между юзерами — каждый аккаунт полностью изолирован.
   Возможно расширим в будущем.
- 🚫 **Расширенная аналитика:** тренды, прогноз, сравнение периодов, графики
   динамики во времени. Только разбивка по категориям за выбранный период.
- 🚫 **Экспорт в CSV/Excel.** Может быть потом.
- 🚫 **Тёмная тема и переключатель тем.** Приложение только светлое
   (light-only): ни авто-тёмной по `prefers-color-scheme`, ни настройки.

## 4. Сущности и их свойства

### 4.1 Категория (`category`)

- **Имя** (строка, обязательно, уникально для пользователя, до 40 символов)
– Описание – до 250 символов
- **Цвет** (выбор из палитры 15 цветов — см. MASTER design system)
- **Дата создания** (auto)

Категории создаются пользователем. Никаких пресетов в БД — у пустого аккаунта
форма траты предложит создать первую категорию налету.

### 4.2 Трата (`expense`)

- **Сумма** (рубли, > 0).
- **Категория** (FK на category, обязательно)
- **Описание** (строка, 1–200 символов, обязательно)
- **Дата траты** (DATE, по умолчанию сегодня в timezone пользователя; нельзя в
  будущем)
- **Дата создания записи** (auto)

Трату можно отредактировать или удалить.

### 4.3 Пользователь

- **email** (уникален)
- **email_verified_at** (timestamp подтверждения email через ссылку из письма)
- **дата регистрации** (auto)

Полная схема, параметры сессий, OAuth и политика account linking —
в [`auth-decisions.md`](./auth-decisions.md). Каждая категория и трата
привязаны к `user_id`, юзеры видят только свои данные (data isolation через
repository pattern + isolation-тесты).

### 4.4 Настройки пользователя (`user_settings`)

- **Дни зарплаты** (`salary_days`) — массив чисел месяца 1–31, отсортирован, без
  дублей; пусто = не задано. Одна строка на пользователя, создаётся лениво при
  первом сохранении. Используется для пресета «с последней зарплаты» в Истории.
- Таблица «на вырост» — сюда лягут будущие пользовательские настройки.

## 5. Экраны и пользовательские сценарии

### 5.1 Главная (`/`)

Что видно сверху вниз:

1. **Шапка:** «moneta» + иконка-шестерёнка → /settings.
2. **Траты за текущую неделю с понедельника** — крупная цифра общего итога
   (₽ X XXX, tabular-nums). Вся карточка кликабельна → История. Разбивки по
   категориям и счётчика трат на главной нет — детали живут в Истории.
   _(Будущее: рядом со тратами — вторая цифра, сводка инвестиций.)_
3. **Форма быстрого ввода:** сумма + категория (Select с inline-«+ Создать»),
   описание, дата (по умолчанию — сегодня), кнопка «Добавить». Категория по
   умолчанию — последняя использованная.
4. **Последние ~10 трат:** компактный список (описание, дата · категория,
   сумма; точка — цвет категории). Строка кликабельна → мини-модалка
   «редактировать / удалить».

Сценарий: открыл, добавил трату → она тут же в «Последних» и в цифре недели;
ошибся — тапнул строку и поправил, не уходя с экрана.

### 5.2 История (`/history`)

1. **Назад на главную.**
2. **Фильтр-период:** два инпута дат «от» и «до» (применяются по уходу из поля /
   Enter), по умолчанию — последние 7 дней. Быстрые пресеты: «7 дней» и «С последней
   зарплаты» (второй показывается, только если в настройках заданы дни зарплаты —
   иначе скрыт). Активный пресет (его диапазон совпадает с выбранным) подсвечен.
3. **Одна карточка** с крупным итогом за период (без заголовка и счётчика трат) и
   двумя вкладками:
   - **«По категориям»** — горизонтальные бары по убыванию суммы (цвет категории,
     длина = доля от итога). Раскрытие категории показывает её траты: описание
     (сверху) и дата (снизу).
   - **«По дням»** — группировка по датам, в заголовке дня — итог за день. Строки:
     цветная точка + описание (сверху) и категория (снизу).
   В обеих вкладках строка траты кликабельна → мини-модалка «редактировать /
   удалить».
4. **Даты** в списках: «Сегодня» / день недели (для последних 7 дней) / «1 июня».

### 5.3 Настройки (`/settings`)

1. **Категории:** список с цветной точкой, иконки «редактировать» и «удалить».
   Под списком — «+ Новая категория». Удалить можно только пустую категорию
   (если есть траты — модалка «у категории N трат, сначала переназначьте или
   удалите траты»). MVP-упрощение: запрещаем удалять непустую категорию,
   reassign-flow откладываем.
2. **Дни зарплаты:** сетка чисел месяца 1–31 (тап — выбрать/снять), можно
   несколько (например 3 и 17). Сохраняются в настройках пользователя. Если
   заданы — в Истории появляется пресет «с последней зарплаты»: диапазон от
   самого позднего наступившего зарплатного дня (в этом месяце, иначе —
   последнего в прошлом) до сегодня; число больше длины месяца зажимается к
   последнему дню. Не заданы — пресет скрыт.
   _(Будущее: тут же — накопления с момента последней зарплаты, пока только
   как информация.)_
3. **Аккаунт:** email пользователя + «Выйти».

### 5.4 Логин и регистрация (`/login`, `/sign-up`)

- **`/login`**: поля email + пароль, кнопка «Войти», кнопка «Войти через
  Google», ссылка «Забыли пароль?». Ошибка всегда generic
  («Неверный email или пароль») — не leak'аем существование email.
- **`/sign-up`**: поля email + пароль, кнопка «Зарегистрироваться», кнопка
  «Зарегистрироваться через Google». После регистрации экран
  «Проверьте почту»: на email пришла ссылка подтверждения. До подтверждения
  доступа в приложение нет.
- **`/verify-email/[token]`**: подтверждение email по ссылке из письма.
- **`/forgot-password`**, **`/reset-password/[token]`**: восстановление
  пароля через email-ссылку.

Поведение OAuth (auto-link по `email_verified`), rate limiting, параметры
сессии — см. [`auth-decisions.md`](./auth-decisions.md).

## 6. UX-принципы

- **Цифра — главный объект.** Шрифт крупный, моноцифровой, выровнен по
  разрядам.
- **Минимум полей, максимум дефолтов.** Сумма, категория и описание —
  обязательные. Дата заранее проставлена сегодня; категория — последняя
  использованная.
- **Mobile-first.** Размеры кликов ≥ 44×44 px, инпуты ≥ 16px текст (чтобы iOS не
  зумил). Decimal keypad для суммы.
- **Никаких эмодзи как иконок.** SVG (Lucide).
- **Только светлая тема.** Light-only — без тёмной и без переключателя в UI.
- **Отзыв на действия:** добавил трату → форма очищается, toast «Готово»,
  сводка обновляется без перезагрузки.

## 7. Будущие итерации (backlog, не для MVP)

Просто чтобы держать направление:

- **Инвестиции** — отдельная страница (портфель / net worth); сводка как вторая
  цифра на главной рядом со тратами (не вместо). Ближайшая планируемая фича.
- Доходы как отдельная сущность (тогда сводка = расходы − доходы).
- Бюджеты помесячно с прогресс-баром на главной.
- Графики динамики (траты по неделям/месяцам).
- Повторяющиеся траты (подписки) с auto-вставкой.
- Несколько валют + конвертация по курсу ЦБ.
- Экспорт в CSV.
- Фото чека (object storage + опц. OCR).
- Webhook от Тинькофф/Сбера для автоматической записи трат.
- Совместные траты / семейный аккаунт (расшаривание категорий и трат
  между несколькими юзерами).

## 8. Definition of Done для MVP

Считаем MVP готовым, когда:

- [ ] Регистрация работает: email+password с подтверждением через
      email-ссылку, плюс «Sign in with Google».
- [ ] На `/login` можно войти подтверждённым аккаунтом (email+password или
      Google).
- [ ] Юзер видит только свои данные — isolation-тест «A не видит данные B»
      проходит для `categories` и `expenses`.
- [ ] На пустом аккаунте форма траты предлагает создать первую категорию.
- [ ] Можно создать категорию (имя + цвет) и сразу записать в неё трату.
- [ ] Главная показывает цифру трат за текущую неделю с понедельника (→ История)
      и список последних трат, всё обновляется без F5 после добавления траты.
- [ ] История с выбранным диапазоном показывает корректные суммы (по категориям
      и по дням) и список; трату из списка можно отредактировать/удалить.
- [ ] Трату можно отредактировать и удалить.
- [ ] Категорию можно отредактировать и удалить (если пустая).
- [ ] В настройках можно задать дни зарплаты (одно или несколько чисел месяца);
      при заданных днях в Истории появляется пресет «с последней зарплаты» с
      корректным диапазоном, при пустых — пресета нет.
- [ ] Все экраны работают на iPhone-ширине (375px) без горизонтального скролла.
- [ ] PWA-манифест на месте, иконку можно установить на главный экран.
- [ ] Postgres и Next.js задеплоены в Coolify на VPS, оба за HTTPS на своих
      субдоменах, ежедневный pg_dump бэкап настроен.
- [x] Домен куплен, DNS-записи для Resend (SPF, DKIM, DMARC, return-path)
      настроены, письма верификации доходят до Inbox (не в спам).
